# Contrato del taller

`OrderUpdate = Partial<Omit<Order, 'id' | 'paid' | 'originalId'>>`: admite únicamente `clientId`, `equipment`, `mode`, `address`, `fault`, `diagnosis`, `parts`, `partsCost`, `labor`, `quote`, `price`, `repair`, `delivery`, `entry`, `finish`, `owner`. Un objeto vacío conserva todo y se persiste. `PaymentInput = { amount: number; date: string }`; fecha nueva ISO calendario `YYYY-MM-DD`. `updateOrder(orderId, patch)` y `registerPayment(orderId, input)` devuelven `Promise<Data>` con el estado recién persistido; las interfaces pueden recibir callbacks async independientes y actualizar la orden por ID desde ese resultado.

Errores `Error` (sin códigos): `No se encontró la orden.`, `La edición contiene campos no permitidos.`, `El precio final no puede ser menor a lo cobrado.`, `El cliente no puede cambiar si rompe una garantía.`, `El importe debe ser un número positivo y finito.`, `La fecha del cobro no es válida.`, `El importe no se puede representar.`, `El cobro supera el saldo pendiente.` La validación preexistente también puede rechazar campos inválidos con `Los datos locales no son válidos. No se modificaron.`; los errores de lectura existentes no cambiaron.

`addClient(input)` conserva su retorno `Promise<Data>`. Para crear y seleccionar inequívocamente, `addClientWithId(input)` devuelve `Promise<{ data: Data; clientId: string }>`: el ID se genera dentro de la misma mutación validada y el resultado se entrega solo si la escritura tiene éxito. Los adaptadores de `CRMRepository` deben implementar ambos métodos; no se identifica al cliente por nombre, teléfono o posición.

Cada operación lee el estado actual dentro de una cola compartida por instancias del mismo contexto, valida y realiza una sola escritura. Web Locks usa `rodrigo-crm` entre pestañas compatibles; sin Web Locks no se garantiza exclusión entre pestañas. Fallos liberan la cola. No hay reembolsos, edición de pagos ni transiciones automáticas. Se conservan discrepancias históricas entre acumulado y registros; precio antiguo inferior a cobrado no impide editar otros campos, y poner precio null conserva cobros. La suma interpreta la representación decimal más corta de cada número, con enteros BigInt, antes de convertir el resultado a number; rechaza resultados que no puedan representarse sin pérdida en esa representación. No modifica números históricos ni impone formato monetario.
