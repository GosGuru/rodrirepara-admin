# Editor inline de órdenes

`OrderEditor({ order, clients, orders, onSave, onCancel })` recibe `Order`, `readonly Client[]`, `readonly Order[]`, `(patch: OrderUpdate) => Promise<void>` y `() => void`. El integrador **debe usar `key={order.id}`** y mantener estable la identidad durante la edición; al cambiar de orden se desmonta el borrador. El padre cierra y refresca tras resolver `onSave`; `onCancel` solo responde a cancelación explícita. El rechazo mantiene el borrador y anuncia `Error.message` o el mensaje genérico. El guardado pendiente bloquea ambos botones y una guarda síncrona evita envíos duplicados.

Edita cliente, equipo, modalidad, dirección, falla, diagnóstico, repuestos, costos, presupuesto, precio, reparación, entrega, ingreso, finalización y responsable. ID, cobrado y vínculo original son informativos; no se editan pagos ni se hacen transiciones automáticas. Una garantía original o derivada bloquea cambiar cliente, no equipo. Entregadas y cerradas se pueden editar. Fechas son texto para conservar formatos históricos; reparación admite estados personalizados. Precio vacío es null, cero es cero; importes requieren números finitos no negativos, y costos vacíos no son cero. El repositorio valida el precio cambiado frente al cobrado actual; un precio histórico inferior no invalida otra edición.

Para un pie externo, `formId?: string` identifica el formulario vivo, `hideActions?: boolean` oculta sus botones internos y `onBusyChange?: (busy: boolean) => void` informa del envío. Los callbacks originales no cambian; el botón externo debe usar `form={formId}` y `type="submit"`.

El borrador y comparación se basan en una instantánea inicial por montaje. El patch incluye solo valores realmente cambiados, sin normalizar campos intactos; una actualización de props del mismo ID no reinicia el borrador ni revierte cambios ajenos. El cobrado mostrado usa las props actuales. El servidor/repositorio sigue siendo autoritativo.

Selectores públicos para integración/pruebas: formulario por nombre accesible `Editar orden <id>`; campos por sus etiquetas españolas; botones `Guardar cambios` y `Cancelar edición`; errores `role=alert`. Al montar se enfoca cliente, o equipo si cliente está bloqueado. Las pruebas SSR solo comprueban estructura y valores iniciales: no prueban foco, callbacks, bloqueo concurrente, conservación del borrador, patch, persistencia ni comportamiento responsive. W3/W4 deben comprobarlos en navegador real, incluidos refresco con el mismo ID, fallos, dobles envíos, garantías, precio histórico y navegación entre órdenes.
